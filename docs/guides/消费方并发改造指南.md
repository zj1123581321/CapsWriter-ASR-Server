# 消费方并发改造指南

ASR 代理按 `task_id` 把任务分发到多台后端。如果消费方仍然一次只发送一个文件或一段音频，代理只能看到一个活跃任务，后端机器不会被充分利用。消费方需要主动并发发起多个独立任务，代理才能把任务分配到不同后端。

## 串行模式瓶颈

常见串行流程如下：

```python
for path in audio_files:
    result = transcribe_one(path)
    save_result(path, result)
```

这种模式的问题是：

- 同一时刻只有一个 `task_id`，代理只能选择一台后端。
- 单个后端慢或临时失败时，整个队列都会等待。
- 多台 Mac / PC 的 ASR 算力无法随文件数量线性释放。

## 改造原则

- 每个文件或独立音频任务使用唯一 `task_id`。
- 每个并发任务建立自己的 WebSocket 连接，或确保同一连接内不同 `task_id` 的收发逻辑能正确匹配结果。
- 并发数建议从后端数量开始，例如 2 台后端先设 `concurrency=2`，再根据显存、CPU 和响应时间调高。
- 失败任务由消费方重试。代理不缓存音频，也不会自动重发任务。

## asyncio 示例

适合已有异步代码或批量转录工具。

```python
import asyncio
import json
import uuid

import websockets


PROXY_URL = "ws://proxy-host:6020"


async def transcribe_one(audio_payload: str) -> dict:
    task_id = str(uuid.uuid4())
    async with websockets.connect(PROXY_URL, max_size=None, ping_interval=None) as ws:
        await ws.send(json.dumps({
            "task_id": task_id,
            "source": "file",
            "data": audio_payload,
            "is_final": True,
            "time_start": 0.0,
            "seg_duration": 15.0,
            "seg_overlap": 2.0,
            "context": "",
            "language": "auto",
        }))

        while True:
            message = json.loads(await ws.recv())
            if message.get("task_id") != task_id:
                continue
            if message.get("is_final"):
                return message


async def transcribe_many(audio_payloads: list[str], concurrency: int = 2) -> list[dict]:
    semaphore = asyncio.Semaphore(concurrency)

    async def run(payload: str) -> dict:
        async with semaphore:
            return await transcribe_one(payload)

    return await asyncio.gather(*(run(payload) for payload in audio_payloads))
```

## 线程池示例

适合同步代码逐步改造。每个线程独立跑一个连接，避免共享 WebSocket 状态。

```python
from concurrent.futures import ThreadPoolExecutor, as_completed


def transcribe_many_sync(audio_payloads, concurrency=2):
    results = []
    with ThreadPoolExecutor(max_workers=concurrency) as pool:
        futures = [pool.submit(transcribe_one_sync, payload) for payload in audio_payloads]
        for future in as_completed(futures):
            results.append(future.result())
    return results
```

## 连接管理

- 最简单可靠的方式是一个任务一条 WebSocket 连接。
- 如果复用一条客户端连接发送多个 `task_id`，必须用 `task_id` 匹配返回消息，不能假设响应顺序和发送顺序一致。
- 任务完成后等待 final `RecognitionMessage`，再关闭连接或释放本地任务状态。
- 收到连接关闭、超时或 WebSocket code `1011` / `1013` 时，把该任务作为失败处理并重新排队。

## task_id

- `task_id` 必须全局唯一，推荐使用 UUID。
- 同一个音频任务的所有分片必须使用同一个 `task_id`。
- 不要在重试时复用已经完成或部分失败的 `task_id`，除非消费方能处理重复结果。

## 并发数建议

以 `config_proxy.py` 中的后端权重为起点：

```text
concurrency ~= sum(weight)
```

例如 Mac Studio `weight=2.0`、Mac mini `weight=1.0`，先从 `concurrency=3` 开始。观察 `logs/proxy_latest.log` 中的 `score`、`avg_latency` 和任务完成时间，再逐步调整。若单机显存或 CPU 长时间满载、latency 明显升高，应降低并发数。
