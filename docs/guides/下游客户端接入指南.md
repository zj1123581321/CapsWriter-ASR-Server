# 下游应用接入指南

CapsWriter ASR Server 通过 WebSocket 提供语音识别。Python 应用推荐使用 [Python SDK](../../sdk/README.md)，它负责音频转码、健康检查、并发收发和错误处理。其他语言可按[服务协议](../reference/protocol.md)直接接入。

## Python 应用

按[首次部署指南](getting-started.md)启动服务，再按 [SDK 文档](../../sdk/README.md)安装并调用 `transcribe_file()`。SDK 客户端需要 `ffmpeg` 和 `ffprobe`；服务端是否需要 FFmpeg 取决于选用的音频编码，具体以 SDK 文档和 `/health` 为准。

## 其他语言的最小流程

1. 对 `http://<host>:6016/health` 发 HTTP GET，确认状态码为 200、`protocol_version` 至少为 2，并检查响应中的 `encodings`。
2. 连接 `ws://<host>:6016`。每条音频帧作为 JSON 文本消息发送，`data` 放音频字节的 Base64 编码。
3. 同一识别任务的帧使用固定的 `task_id` 和 `encoding`。PCM 可使用 16 kHz、单声道、int16 little-endian（`s16le`）；不要把 WAV 文件头当作 PCM 数据发送。
4. 末帧设置 `is_final: true`，并提供整段解码后的样本数 `samples_total`。没有剩余音频时，末帧可以发送空 `data`。
5. 上传期间并发读取服务端消息；继续接收进度结果，直到 `is_final: true`。收到错误消息、最终结果前连接关闭或读取失败，都应判定本次任务失败。

字段、末帧规则、错误码与兼容行为统一见[服务协议](../reference/protocol.md)。不要在下游指南中复制协议字段表。

仓库提供[最小 WebSocket 示例](../../examples/websocket_transcribe.py)，仅接受 16 kHz、单声道、PCM16 WAV 短音频，不负责通用媒体转码。从仓库根目录运行：

```bash
python -m pip install 'websockets>=15.0.1'
python examples/websocket_transcribe.py input.wav --url ws://127.0.0.1:6016
```
