阶段：planning → complete；三平台只读盘点完成，未执行任何隔离运行。

结论：三平台（macOS 两台、Windows 一台、Linux 开发机一台）全部探测成功，每台一次有界只读 ssh/stdin 脚本，无重扫。三台在跑的服务 `git_sha` 均为 `6b7a2b8`，已本地核实它是当前 HEAD `5134720` 的祖先——生产跑的不是待验收代码。Git 内确认零音频 fixture，但 P4 的 gitignored 临时目录里有真实素材（77.184 秒视频、同长 16 kHz 提取音频、55–77 秒片段、三倍长拼接、一份 79 行字幕），字幕与音频的对应关系**未验证**。仓库已有被跟踪的 CER 基线工具 `scripts/_baseline_asr.py`（真实 WS producer 字节 + CER + 耗时 + 时间戳不变量），但只覆盖 WS、不覆盖 HTTP，且缺「字幕归一化为纯文本」的规则。P1、P3 是生产且被占满；P2 当前无监听但缺 Python 3.12 与 ffmpeg、部署非 git；P4 解释器与 ffmpeg 齐备、出网通，但无 ASR 权重与推理后端。

决策与否决：否决「在生产机 P1/P3 上起隔离实例」——需另授权，且 P3 的启动批处理会结束所有 Python 进程，风险外溢。否决「把本地 gitignored 素材当正式参考稿」——来源授权与字幕对应关系均未证。否决「用 P2 部署目录的运行版本作证据」——非 git 部署，无 HEAD 可查，只能记访问未知。否决在本卡内下任何平台已验证的结论——只有原始探针状态可作依据。
