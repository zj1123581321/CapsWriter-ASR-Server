# 下游应用接入指南

CapsWriter ASR Server 提供 WebSocket 语音识别接口，适合接入桌面应用、机器人、视频处理工具和其他服务。Python 项目推荐使用 [SDK](../sdk/README.md)：SDK 负责音频转码、服务端健康检查、并发收发和错误处理。其他语言可以直接实现[协议 v2](protocol.md)。

## Python：使用 SDK

按[入门指南](getting-started.md)启动服务并确认 `/health` 返回成功。客户端需要安装 `ffmpeg` 和 `ffprobe`；SDK 安装和最小调用见 [Python SDK 文档](../sdk/README.md)。默认 URL 为 `ws://127.0.0.1:6016`。

SDK 默认把输入文件转成 FLAC，也可选择 `ogg_opus`、`f32le` 或 `s16le`。默认 FLAC 编码要求服务端 PATH 中有 `ffmpeg`，且 `/health.encodings` 包含 `flac`；首次部署可显式选择 `s16le`，服务端不需要 FFmpeg。服务端必须报告协议版本 2 并支持所选编码；否则调用会抛出 `AsrError`。SDK 客户端无论选何种编码，仍需本机 `ffmpeg` 和 `ffprobe`。SDK 不自动切换到旧协议或重试。

## 其他语言：实现 WebSocket v2

1. 对 `http://<host>:6016/health` 发 HTTP GET，确认状态码为 200、`protocol_version` 至少为 2，并检查返回的 `encodings`。
2. 连接 `ws://<host>:6016`。每条音频帧发送为 JSON 文本消息，`data` 是音频字节的 Base64 编码。
3. 每个任务使用固定的 `task_id` 和 `encoding`。PCM 推荐使用 16 kHz、单声道、int16 little-endian (`s16le`)；不能发送带 WAV 头的 PCM 数据。
4. 末帧设置 `is_final: true`，并带上整段解码后样本数 `samples_total`。末帧可以携带最后一块音频，也可以在没有剩余数据时发送空 `data`。
5. 上传期间并发读取服务端消息。处理 `type: "result"` 的进度消息，直到收到 `is_final: true`。收到 `type: "error"`、连接在最终结果前关闭或读取失败，都必须按失败处理。

仓库的[最小 WebSocket 示例](../examples/websocket_transcribe.py)包含短音频 WAV 格式校验、v2 JSON 帧和并发收发。它只接受 16 kHz、单声道、PCM16 WAV，不是通用媒体转码器。其他格式请先转码，例如：

```bash
ffmpeg -nostdin -i input.m4a -ar 16000 -ac 1 -c:a pcm_s16le output.wav
```

协议字段、编码要求、v1 兼容行为和错误码详见[服务协议](protocol.md)。

## 识别结果

服务端返回 `text`、`text_accu`、`tokens`、`timestamps` 和 `duration` 等字段。不同模型的 token 粒度可能不同；生成字幕时应直接配对使用本次结果中的 `tokens` 与 `timestamps`，不要从 `text` 重新切词后推算索引。时间戳单位为秒，具体结果取决于所选模型与当前服务端实现。
